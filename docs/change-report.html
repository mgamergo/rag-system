Change report: web-only RAG

The web is now the only interface, backed by a shared engine and Convex manifests. This report records the option replacements, data model, verification and remaining limitations.

Final architecture

Next.js controls call Convex Node actions; shared domain/pipeline modules implement all retrieval and ingestion behavior. Convex transactions persist immutable chunks, vectors and manifests, with atomic document activation. Exact model-filtered cosine replaces approximate vector search for parity and variable dimensions. Original lexical statistics, tokenizer, RRF, prompt and evaluator formulas are retained.

Changed or dropped

  • CLI modules/scripts and Commander are removed. Paths become uploads, document selection, saved runs and downloads.
  • Transformers/local ONNX and local cross-encoder are replaced by hosted OpenRouter/Voyage/Gemini embeddings and Cohere/Voyage reranking.
  • Localhost Ollama/base URL and device selection are removed; generation uses OpenRouter. Hosted model outputs are not numerically identical to local models.
  • Existing model override environment behavior becomes an explicit persisted UI value.
  • SHA-256 replaces the existing 32-bit contentHash algorithm; content plus config defines deduplication, allowing changed-config experiments.
  • Legacy data is preserved but requires re-upload. No migration deletes files or database rows.

Data model and functions

  • documents: filename, content/config hashes, config JSON, current chunk/vector run pointers and indexing state.
  • chunks: immutable original text, separate generated context, code-point offsets and engine IDs.
  • vectors: variable-dimension embeddings keyed by run, model, document and chunk.
  • runs: ingestion/re-embedding kind, resolved config, state, usage/error and timestamps.
  • traces: success/failure, question/answer, source snapshot/run versions, model/config, usage and latency.
  • evaluations: gold dataset, config, selected IDs, versioned reports, status/error and timestamps.

Public actions: rag.ingest, rag.ask, rag.reembed, rag.exportDocument, rag.runEvaluation. Public read queries: documents.list, runs, traces, evaluations. Internal mutations: reserve, beginReembed, addBatch, finish, startTrace/endTrace, startEvaluation/endEvaluation. Internal queries: selection, chunkPage, vectorPage. Configs have Convex shape validators plus shared Zod conditional validation.

Verification

Passed npm run check:all: root and web typecheck, lint, all 44 engine/provider tests and 10 Convex integration tests, root compilation and Next.js production build of / and /evals. The web build used a placeholder Convex URL. Also passed root formatting check, offline embedding contract smoke check and Git whitespace check. CI workflow now runs web tests; the checks were executed locally on Windows rather than in an Ubuntu Actions runner. No paid APIs, live deployment or browser/backend smoke test were used. Documentation HTML was checked by source/read-through; it was not browser-rendered.

Known gaps

  • No auth/tenant isolation; restrict deployment access before sharing.
  • Exact scans and synchronous actions suit bounded corpora. No durable/resumable workers or interrupted-run recovery.
  • Caps: 8 upload files, 500,000 code points per file, 10,000 chunks/document/snapshot, 200 eval questions, request timeouts up to 600 seconds.
  • Evaluation per-query latency excludes initial snapshot loading. Question trace total latency includes loading; retrieval-stage latency covers the shared engine only.
  • No input token budget, automatic retries, citation verifier, answer-quality grader or price calculation. Failure traces do not retain partial stage/source usage after exceptions. Client-side decode failures are displayed while other files continue; they do not create Convex runs.
  • Historical/failed runs are retained with no cleanup UI. Duplicate filenames make source labels ambiguous; use chunk IDs.
  • No paid inference, actual deployment or live browser/backend smoke test is part of offline verification.
