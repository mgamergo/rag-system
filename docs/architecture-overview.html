Shared RAG architecture

One web interface calls one shared RAG engine. Convex owns persistence; the domain and pipeline modules do not depend on Convex.

Ownership

  • src/domain defines schemas, defaults, records and inference ports.
  • src/ingestion, embeddings, retrieval, generation and evaluation own reusable behavior.
  • src/pipelines composes corpus-in/corpus-out operations.
  • web/convex/rag.ts uses the Node runtime for actions, hashes and provider requests.
  • web/convex/documents.ts owns queries/mutations and immutable-run activation.
  • Browser controls are shared between the workspace and evaluation page.

Why exact retrieval

Exact cosine preserves the former CLI behavior and handles variable model dimensions. Filter documents and embedding model before loading/scoring vectors. BM25 and TF-IDF rebuild the original statistics from stored context plus text; full-text substitution would change tokenizer and ranking behavior. Exact retrieval scans the selected corpus and is capped at 10,000 chunks.

Data lifecycle

A normalized upload plus complete ingestion config produces SHA-256 deduplication keys. An immutable run stages chunks/context/vectors. A transaction switches the document active-run pointer after every batch succeeds. Re-embedding creates a new vector run while retaining the original chunk run. A failure leaves old evidence active.

Legacy data and deployment

Existing pre-manifest rows remain stored, but are excluded from the new corpus until re-uploaded. Old fixed-dimension vector indexes are no longer queried. No automatic destructive migration or deployment is performed.

Limits

Local models and localhost Ollama are replaced by hosted providers. No auth, token-window fitting, citation enforcement or resumable worker exists. Model calls can cost money. Action deadlines still apply.
